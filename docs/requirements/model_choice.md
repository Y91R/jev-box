# СТ: автоматический выбор модели Claude плагином на Function Hooks

## Цель и границы

Плагин Claude Code `jev-box` на каждый ход пользователя и на каждый запуск сабагента выбирает модель Claude из списка, который задал пользователь. Решение принимает классификатор Jev от TypeSafe. Вызывается он либо напрямую у TypeSafe, либо через OpenRouter. Цель — не держать всю сессию на одной модели: простые задачи отдавать дешёвой модели, сложные — сильной.

Входит в объём:
- выбор модели главного цикла на каждый ход;
- выбор модели сабагентов тех типов, что перечислены в конфиге;
- два провайдера доступа к Jev: TypeSafe (напрямую) и OpenRouter; в каждый момент активен ровно один;
- конфиг и ключи в `~/.config/jev-box/config.json`;
- список доступных моделей задаётся в этом файле.

Не входит в объём (решения пользователя от 2026-09-22 [9]):
- выбор `effort`: он остаётся от сессии, плагин его не меняет (FR-11);
- перевод самого Claude Code на модели OpenRouter (GPT, Gemini и т.п.). OpenRouter используется только как канал доступа к Jev. `turn.step` позволяет менять лишь `model` и `effort`, провайдера запроса он не меняет [1];
- slash-команда или UI для правки списка моделей: список правится только в файле;
- резервный провайдер: при сбое активного ход идёт на модели сессии;
- раздельное хранение ключей: ключи лежат в `config.json` рядом с настройками;
- ограничение размера текста, который уходит классификатору. Промпт отправляется целиком. Если он слишком велик, провайдер отвечает ошибкой либо срабатывает таймаут, и результат — «нет решения» (FR-21);
- учёт `XDG_CONFIG_HOME`: путь фиксирован относительно `HOME` (решение аналитика).

## Глоссарий

- **Function Hooks** — preview-механизм Claude Code: TypeScript-модули плагина, которые оборачивают события движка как middleware `($, e, next)`. Включается переменной `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` [1][2].
- **Главный цикл** — цикл модели основной сессии. Его события `turn.step` идут без `agentId` [1].
- **Ход** — обработка одного промпта пользователя в главном цикле, от `turn.start` до `turn.complete`. Идентифицируется `turnId`. Ход состоит из одного или нескольких шагов `turn.step`, каждый шаг — отдельный запрос к API [1].
- **Модель движка** — значение `model` во входе `turn.step`, то есть модель, которую движок назначил шагу сам: модель сессии или резервную [1].
- **Классификатор** — модель Jev, которая по тексту задачи выбирает модель из списка кандидатов.
- **Провайдер** — канал, через который вызывается Jev: `typesafe` (API TypeSafe) или `openrouter` (Decisions API OpenRouter).
- **Jev** — модель класса System One от TypeSafe. Возвращает типизированный ответ с вероятностями и `confidence` [3][4].
- **Разрешённый список** — модели из поля `models` конфига.
- **Кандидаты** — модели разрешённого списка, которые можно предложить классификатору прямо сейчас (FR-8, FR-15).
- **Текст задачи** — строка, которая уходит классификатору (FR-7, FR-15).

## Акторы и роли

| Актор | Роль |
|---|---|
| Пользователь | Правит `config.json`: провайдер, ключи, список моделей, типы сабагентов. Работает в Claude Code как обычно. |
| Claude Code (движок) | Поднимает события `session.start`, `turn.start`, `turn.step`, `turn.complete`, `agent.spawn` и отправляет запросы к модели с тем `model`, который вернула цепочка хуков [1]. |
| TypeSafe API | Внешний классификатор, отвечает на вопрос `choice` [4][5]. |
| OpenRouter API | Канал доступа к Jev через Decisions API, отвечает на тот же вопрос `choice` [6][7]. |

## Функциональные требования

### Конфигурация

- **FR-24.** Система должна работать, только если переменная окружения `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` задана и не пустая. Значение читается через `$.env.get("CLAUDE_CODE_ENABLE_FUNCTION_HOOKS")`. Без переменной каждый хук передаёт событие без изменений (`next(e)`): конфиг не читается, запросов к провайдерам и строк в лог нет. Сейчас рантайм без флага хуки не загружает [2], так что требование страхует на случай выхода Function Hooks из preview. Источник: решение пользователя от 2026-09-22 [9]. Номер FR-24 дан, чтобы не перенумеровывать остальные требования.
- **FR-1.** Система должна читать конфиг из файла `<HOME>/.config/jev-box/config.json`, где `<HOME>` — значение переменной окружения `HOME`, полученное через `$.env.get("HOME")`. Путь `~` движок не раскрывает [1]. Источник: [9]; [1].
- **FR-2.** Система должна перечитывать конфиг перед каждой классификацией (FR-7, FR-15), чтобы правки файла действовали без перезапуска сессии. Источник: вывод аналитика из FR-1 и выноса UI за скоуп.
- **FR-3.** Система должна применять конфиг, только если он проходит все проверки FR-4. Иначе он не применяется целиком.
- **FR-4.** Конфиг считается невалидным, если нарушено хотя бы одно правило:
  1. `HOME` не задан, файла нет, чтение файла завершилось ошибкой или содержимое не парсится как JSON-объект;
  2. `provider` не равен строке `typesafe` или `openrouter`;
  3. `models` — не массив, пустой массив или его элемент не объект;
  4. у элемента `models` поле `id` или `description` не является непустой строкой;
  5. в `models` повторяются `id`;
  6. у элемента `models` поле `contextWindow` не является целым числом больше 0;
  7. в `models` больше 255 элементов: это лимит вариантов `choice` у Jev [4];
  8. поле `timeoutMs` задано, но не является целым числом от 1 до 9000;
  9. поле `subagentTypes` задано, но не является массивом непустых строк;
  10. в секции активного провайдера `apiKey` не является непустой строкой;
  11. поле `typesafe.model` задано, но не является непустой строкой;
  12. поле `minConfidence` задано, но не является числом от 0 до 1 включительно;
  13. поле `openrouter.model` задано, но не является непустой строкой;
  14. поле `contextReserve` задано, но не является числом больше 0 и не больше 1.

  Источник: вывод аналитика из схемы конфига; п. 7 — [4].
- **FR-5.** При невалидном конфиге система должна пропускать все события без изменений (`next(e)`). Строка через `$.ui.log` с номером нарушенного правила FR-4 и именем поля выводится один раз за сессию: на `session.start`, если конфиг уже невалиден, либо при первой классификации, на которой он оказался невалидным. Источник: вывод аналитика из [1] (`$.ui.log`). Сессия заканчивается событием `session.end` (выход, `/clear`, resume), после которого признак «строка уже выведена» сбрасывается: `session.start` после `/clear` не приходит [1], и без сброса новая сессия осталась бы без строки. Источник: [1] (`session.start`, `session.end`); ревью кода от 2026-09-22.
- **FR-6.** Система не должна выводить значения `apiKey` в транскрипт, лог, `$.store` или тексты ошибок. Источник: [9]; вывод аналитика.

### Выбор модели главного цикла

- **FR-7.** На `turn.start` с непустым `text` система должна запустить классификацию. Текстом задачи служит `text` как есть. Если `text` пустой (продолжение хода без промпта [1]), классификация не запускается и ход идёт на модели движка.
- **FR-8.** Перед классификацией главного цикла система должна получить заполнение контекста: `$.session.usage()` → `context.tokens` [1]. Кандидатами остаются модели, у которых `contextWindow × contextReserve` не меньше этого значения (по умолчанию `contextReserve` = 0.5: текущий контекст занимает не больше половины окна модели). Запас нужен потому, что `context.tokens` — это вход только последнего ответа [1], а внутри хода к нему добавляются этот ответ, новый промпт и результаты инструментов. Если `context.tokens` отсутствует (ответов ещё не было [1]), кандидаты — весь разрешённый список. Если кандидатов нет, результат — «нет решения» без запроса к провайдеру. Цель — не переводить длинную сессию на модель с меньшим окном, иначе ход завершится ошибкой лимита контекста [1] (`TurnCompleteReason`: «the context limit»). Источник: [9] (запас 50% — решение пользователя от 2026-09-22 по итогам ревью кода); [1].
- **FR-9.** Система должна классифицировать активным провайдером по FR-17 или FR-18. Результат — выбранный `id` или «нет решения» — хранится в памяти модуля под ключом `turnId` вместе с моделью движка первого шага хода (FR-10).
- **FR-10.** На каждом `turn.step` без `agentId` система должна:
  1. на первом шаге с `index = 0` запомнить `e.model` как модель движка этого хода и больше её не перезаписывать: повторный шаг 0 на другой модели считается переходом на резервную; если шаг 0 до плагина не дошёл, модель в этом ходе не подменяется;
  2. если для хода есть выбранный `id` и `e.model` совпадает с запомненной моделью движка, передать дальше `next({ ...e, model: <id> })`;
  3. если `e.model` отличается от запомненной (движок перешёл на резервную модель [1]), передать шаг без изменений.

  Модель выбирается один раз на ход и внутри хода не пересчитывается: prompt cache привязан к модели, и каждая смена модели означает запись контекста в кэш заново (см. поле `prompt_cache_warm` в `PreModelSwitch` [1]). Источник: [1] (`TurnStepInput.model` переписываемо; «the session's, a fallback's»); п. 3 — вывод аналитика.
- **FR-11.** Система не должна менять `effort` шага: при подмене по FR-10 поле `effort` передаётся дальше как есть. Движок сам не передаёт `effort` модели без его поддержки: 2026-09-22 на Claude Code 2.1.278 подмена `claude-opus-5` с `effort: high` на `claude-haiku-4-5` (Haiku 4.5 `effort` не поддерживает) прошла без ошибки и с оставленным `effort`, и со сброшенным. Источник: проверка на шаге 1a плана `docs/plans/hashed-seeking-clover.md`; решение пользователя от 2026-09-22 [9].
- **FR-12.** Если `turn.step` пришёл раньше, чем закончилась классификация этого хода, шаг должен дождаться её результата. Ожидание ограничено таймаутом FR-19. Источник: вывод аналитика из FR-10, FR-19. Если ход прерван (`next.signal` отменён [1]), шаг перестаёт ждать и `next` не вызывает: движок к этому моменту уже продолжил без хука, а ожидание дольше `HookBudget.lingerMs` (5000 мс [1]) помечает хук как зависший.
- **FR-13.** Если для хода «нет решения», система должна передать `turn.step` без изменений.
- **FR-14.** На `turn.complete` без `agentId` система должна удалить запись этого `turnId` из памяти. Событие приходит при любом исходе хода: `answer`, `aborted`, `refusal`, `error` [1].

### Выбор модели сабагента

- **FR-15.** На `agent.spawn` система должна запустить классификацию, если выполнены все условия:
  - `fork = false`: для форков `model` игнорируется [1];
  - `model` не задан вызовом (`undefined`): явный выбор модели в вызове Agent остаётся в силе (решение аналитика);
  - `subagentType` входит в `subagentTypes` конфига (по умолчанию `["general-purpose"]`). Модель из файла определения агента в `agent.spawn` не передаётся [1], поэтому ограничение по типам не даёт плагину молча перекрыть её у остальных агентов (решение пользователя [9]).

  Текст задачи — строка `description`, два перевода строки, затем `prompt`: `` `${description}\n\n${prompt}` ``. Кандидаты — весь разрешённый список: сабагент стартует с собственным контекстом. Источник: [9]; [1].
- **FR-16.** Если выбрана модель, система должна передать дальше `next({ ...e, model: <id> })`. Если «нет решения» — `next(e)` без изменений. Шаги сабагента (`turn.step` с `agentId`) система не меняет. Источник: [1] (`AgentSpawnInput.model`). Если запуск прерван (`next.signal` отменён [1]) во время классификации, система должна перестать ждать и ответить `{ deny: "jev-box: spawn aborted" }`, не вызывая `next`, чтобы после отмены не стартовал сабагент.

### Провайдеры классификации

- **FR-17. TypeSafe.** Система должна отправить `POST https://api.typesafe.ai/v1/systemone` с заголовками `Authorization: Bearer <typesafe.apiKey>` и `Content-Type: application/json`. Тело запроса:
  ```json
  {
    "model": "<typesafe.model>",
    "state": "<текст задачи>",
    "questions": {
      "model": {
        "type": "choice",
        "instructions": "Which Claude model should handle this task?",
        "criteria": { "<кандидат.id>": "<кандидат.description>" }
      }
    }
  }
  ```
  Ответ принимается, если `answers.model.choice` — строка. Если задан `minConfidence`, то при `answers.model.confidence`, которое не является числом или меньше порога, результат — «нет решения». Источник: [4][5].
- **FR-18. OpenRouter.** Система должна отправить `POST https://openrouter.ai/api/alpha/decisions` с заголовками `Authorization: Bearer <openrouter.apiKey>` и `Content-Type: application/json`. Тело запроса такое же, как в FR-17, только `model` = `openrouter.model`. Ответ разбирается так же, как в FR-17: `answers.model.choice` и порог `minConfidence`. У OpenRouter поле `confidence` необязательно [6]: если порог задан, а `confidence` нет, результат — «нет решения». Адрес проверен запросом без ключа 2026-09-22: ответ 401. Адрес `https://openrouter.ai/api/v1/api/alpha/decisions` из справочника [6] отвечает 404. Источник: [6][7].
- **FR-19.** Система должна ограничивать ожидание ответа классификатора величиной `timeoutMs` (по умолчанию 3000 мс). Отсчёт идёт от вызова `$.http.fetch` до получения ответа. У `$.http.fetch` нет своего таймаута [1], поэтому ограничение делается на стороне плагина. После таймаута результат — «нет решения», а пришедший позже ответ игнорируется. Источник: [9] (3 с); [1].
- **FR-20.** Результат принимается, только если выбранный `id` есть среди кандидатов. Иначе результат — «нет решения». Источник: вывод аналитика: ответ Jev приходит по сети, и его соответствие списку `criteria` плагин проверяет сам.
- **FR-21.** Система должна сводить к «нет решения» каждый из отказов ниже и присваивать ему код причины:

  | Отказ | Код |
  |---|---|
  | `$.http.fetch` отклонён: сеть, DNS, TLS, запрет политикой администратора [1] | `network` |
  | Истёк `timeoutMs` (FR-19) | `timeout` |
  | HTTP-статус не 2xx (TypeSafe: 401, 422, 429, 529 [5]; OpenRouter: 400, 401, 402, 403, 404, 413, 429, 500, 502, 503, 524, 529 [6]) | `http_<статус>` |
  | Тело не парсится или поля ответа не проходят проверку FR-17/FR-18 | `bad_response` |
  | Выбранный `id` не среди кандидатов (FR-20) | `unknown_model` |
  | Любое другое исключение внутри хука | `internal` |

  Отказ одного провайдера не переключает на другой. Источник: [9]; [1][5][6].
- **FR-22.** При каждом отказе по FR-21 система должна вывести через `$.ui.log` одну строку: провайдер, если он уже известен из конфига, и код причины. Тело ответа и ключ в строку не попадают. Не считаются отказами и не логируются: низкая уверенность по FR-17/FR-18 и пустой список кандидатов по FR-8. Источник: вывод аналитика из FR-6, FR-21.
- **FR-23.** Все HTTP-запросы к провайдерам система должна выполнять только через `$.http.fetch`: собственная сеть плагину недоступна [1].

### Сценарий: ход пользователя

Основной поток:
1. Пользователь отправляет промпт.
2. `turn.start` → плагин читает конфиг (FR-2), отбирает кандидатов по окну контекста (FR-8) и отправляет запрос активному провайдеру (FR-17/FR-18).
3. Приходит выбранный `id`, он есть среди кандидатов.
4. Каждый `turn.step` главного цикла этого хода уходит с этим `model` (FR-10), `effort` не меняется (FR-11).
5. `turn.complete` → запись удаляется (FR-14).

Альтернативные потоки:
- Конфиг невалиден → строка в лог один раз за сессию, ход без изменений (FR-5).
- Нет кандидатов с достаточным окном → ход на модели движка без запроса к провайдеру (FR-8).
- Отказ по FR-21 → строка в лог, ход на модели движка (FR-21, FR-22).
- `confidence` ниже порога или отсутствует при заданном пороге → ход на модели движка без лога (FR-17, FR-18).
- Движок перешёл на резервную модель посреди хода → шаг без изменений (FR-10).
- Пустой `text` → классификации нет (FR-7).

## Модель данных

### Файл `~/.config/jev-box/config.json`

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `provider` | `"typesafe"` \| `"openrouter"` | да | Активный классификатор. |
| `models` | массив объектов, 1–255 | да | Разрешённый список. |
| `models[].id` | непустая строка | да | Полный ID модели Claude (например, `claude-opus-5`, `claude-sonnet-5`, `claude-haiku-4-5`, `claude-fable-5-1`). Уникален в списке. Что `agent.spawn` принимает и алиас, и полный ID, в типах сказано [1]; принимает ли `turn.step` алиас при подмене, не подтверждено. Поэтому используются только полные ID (решение аналитика). |
| `models[].description` | непустая строка | да | Когда выбирать модель. Уходит в `criteria` вопроса к Jev. |
| `models[].contextWindow` | целое > 0 | да | Окно контекста модели в токенах. Нужно для отбора кандидатов (FR-8). |
| `subagentTypes` | массив непустых строк | нет | Типы сабагентов, модель которых выбирает плагин. По умолчанию `["general-purpose"]` (FR-15). |
| `timeoutMs` | целое 1–9000 | нет | Таймаут классификации, по умолчанию 3000. Верхняя граница — из лимита времени хука 10 000 мс (`HookBudget.ms` [1]). |
| `contextReserve` | число в (0; 1] | нет | Какую долю окна модели может занимать текущий контекст, чтобы модель осталась кандидатом (FR-8). По умолчанию 0.5. |
| `minConfidence` | число 0–1 | нет | Порог `confidence`, общий для обоих провайдеров. Если не задан, порог не применяется. Значения по умолчанию в источниках нет. |
| `typesafe.apiKey` | непустая строка | да, если `provider = typesafe` | Ключ TypeSafe. |
| `typesafe.model` | непустая строка | нет | Модель Jev, по умолчанию `jev-latest` [5]. |
| `openrouter.apiKey` | непустая строка | да, если `provider = openrouter` | Ключ OpenRouter. |
| `openrouter.model` | непустая строка | нет | ID модели Jev в OpenRouter, по умолчанию `~typesafe/jev-latest` («always redirects to the latest model in the Jev family» [7]). В примерах API указан `typesafe/jev-1.13` [6]. |

### Состояние в памяти модуля

- `Map<turnId, { engineModel?: string; decision: Promise<id | none> }>` — решения по ходам главного цикла. Запись создаётся в FR-9, `engineModel` заполняется в FR-10, запись удаляется в FR-14.
- Признак «строка о невалидном конфиге уже выведена» (FR-5).

На диск и в `$.store` ничего не пишется.

## Интеграции

| Система | Направление | Транспорт | Что передаётся | Ошибки |
|---|---|---|---|---|
| TypeSafe API [5] | плагин → TypeSafe | HTTPS POST JSON, `$.http.fetch` | Текст задачи (FR-7, FR-15), `id` и `description` кандидатов | FR-19, FR-21 |
| OpenRouter Decisions API [6] | плагин → OpenRouter (`/api/alpha/decisions`) | HTTPS POST JSON, `$.http.fetch` | То же | FR-19, FR-21 |
| Claude Code [1] | движок ↔ плагин | Function Hooks: `session.start`, `turn.start`, `turn.step`, `turn.complete`, `agent.spawn`; `$.session.usage` | `model` и `effort` шага, `model` сабагента | Хук не пробрасывает исключение в движок: любая внутренняя ошибка сводится к `next(e)` с кодом `internal` (FR-21) |

Текст промптов пользователя и заданий сабагентов уходит внешнему провайдеру целиком. Пользователь соглашается на это, когда задаёт `provider` и ключ в конфиге.

## Нефункциональные требования

- **NFR-1.** Плагин работает только при заданной `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` (FR-24) на сборке Claude Code с preview-рантаймом Function Hooks. Рантайм проверен на локальной установке 2.1.278 (2026-09-21). По сторонним статьям [10] он доступен с 2.1.260; это вторичный источник. Контракт событий сверяется с `mods/types/claude-code.d.ts` апстрима [1].
- **NFR-2.** Ожидание ответа классификатора, от вызова `$.http.fetch` до получения ответа или таймаута, не превышает `timeoutMs` (FR-19).
- **NFR-3.** Структура плагина соответствует модам апстрима: `.claude-plugin/plugin.json`, `hooks/hooks.json` со списком `modules`, `hooks/register.ts` с `register(on, options)` [8].
